## Final product and support boundary

Qualify the installed Blender extension's active WCSPH solver, CUDA Graph/eager paths, GPU-resident SoA state, same-device CUDA/OpenGL VBO transport, particle/sphere/SSFR display, two Quick-Run demos, runtime installer and complete public start/pause/step/resume/stop lifecycle. Preserve zero per-frame simulation readback and graph-safe allocation rules in `AGENTS.md`.

The manifest supports Linux x64 and Windows x64, minimum Blender 5.2.0. First Linux certification is proposed for Debian 13.6 x86_64/glibc 2.41, stock official Blender 5.2.0 and a separately reported 5.2.2 compatibility row. `AGENTS.md` and current lock override the older spec's broad Warp 1.16+ wording: exact `warp-lang==1.17.0`, certified CUDA 12.9 PyPI wheel, private extension storage, compatible NVIDIA driver (repository floor 525), OpenGL 4.5+ Core Profile and dynamic `libcudart.so.12`. Record the actual CUDA runtime/driver compatibility; the stated floor alone is not execution evidence. OpenGL and Warp `cuda:0` must be the same physical NVIDIA GPU. Freeze GPU model/UUID/VRAM/driver/display/session before execution; only measured rows can be claimed supported.

The 1M–4M particles at 50+ FPS objective in `docs/SPEC_AND_PLAN.md` is a product target, not a current certification result. A release claim needs a frozen scene/particle/substep/render/resolution/timing profile before measurement. IPBF integration, two-way arbitrary mesh coupling, live whitewater, neural/FNO and SplashSurf production workflows are scaffolded or future work in that spec; do not enlarge this active-runtime certificate to them. Their existing unit tests can be reported separately. An active-runtime pass cannot be called certification of the entire final-product roadmap. The future/full-product matrix below keeps those original goals open until implemented and qualified or an explicitly accepted narrower product scope is recorded.

## Gates, artifacts and invalidation

PASS requires successful exit, explicit result, exact identities, expected positive output and successful controls for that claim. FAIL means an observed violated requirement (currently the two demo tracebacks). BLOCKED means an unavailable mandatory prerequisite, such as NVIDIA/GL, migration predecessor or accepted performance profile. NOT_RUN means no execution. INCONCLUSIVE includes timeout, lost process, missing terminal summary, malformed/mismatched evidence or unmeasurable timing. A required skipped test remains open and prevents full certification. Unit/mock passes stay source-only.

Every run preserves candidate/dirty file map, package and installed byte hashes, pinned dependencies and actual imported paths, Blender/Python/GPU/driver/GL identity, argv/cwd/environment/start/end/exit records, complete logs, test summaries and skips, controls/workflow JSON, exact input/scene/seed/settings, actual captures and exported fixtures, raw frame/timing/resource samples, and an evidence SHA manifest. Keep failed attempts immutable, with a reasoned supersession link. Historical Windows reports and CPU data must remain labelled by their actual boundary.

Any code/package/lock/driver/Blender/shader/fixture/verifier/threshold change invalidates dependent evidence. Error-presentation correction needs both demo negative controls and rebuilt installed UI/lifecycle regression; physics/interop/render changes require their focused red/green control, full source suite, actual CUDA/GL/SSFR workflow and performance matrix. Final same-hash ZIP must pass required release rows after all changes. A documentation-only edit does not justify another broad GPU run.
